# 找人 (Find On-Call Person)

## 工作流程

> **路径优先级（重要）**：步骤 1 → 步骤 2 → 步骤 3 → 步骤 4，**禁止跨步骤合并**。任一步骤成功命中即输出结果，不再执行后续步骤。步骤 4 是终极人工兜底（@Sunway Zhong），仅在前 3 步全部失败时进入。

### 步骤 1：查找值班人 (优先)

1. **获取模块列表**：静默执行 `/oncall --list` 获取所有可用的值班模块及其描述。
2. **匹配模块**：根据用户的具体问题描述，与获取到的列表进行语义匹配，找出最合适的 `<module>`。
   - **匹配判定**：仅当用户问题描述与某个模块的描述存在明确语义重合（关键词命中或同义词映射）时视为匹配成功。**模糊或低置信度的猜测不算命中**，应视为未匹配。
   - **未命中处理**：若模块列表中没有任何模块与用户问题对应，立即终止当前步骤，跳转至 **步骤 2**。
3. **获取值班人**：执行 `/duty <module>` 获取该模块的主备值班人。**主值班人 = 列表的第一个人员**。
4. **工单创建判断**：
   - 仅当用户在上下文中**明确表达**了"拉群"、"建单"、"需要找他看问题"等意图时，从用户原始提问中提取 `<title>` (默认: "问题咨询")，执行 `/oncall <module> <title>`。
   - 若用户仅询问"谁负责"，则停止操作，直接汇报值班人结果。

### 步骤 2：基于组织架构查找负责人 (备选)

如果 **步骤 1** 无法匹配到对应的值班模块，则切换到组织架构检索路径，按以下子步骤精确定位负责人：

1. **加载部门索引**：阅读 `references/technology-center/README.md`，使用其中的"路由关键词 → 详情文件锚点"表完成路由。**README.md 仅含索引，不含具体姓名**，所有姓名以详情文件为唯一事实源。

2. **匹配子团队**：把用户关键词路由到 README.md 中**最具体的子小节**（1.1 / 1.2 / 1.3）。具体路由规则与关键词列表已在 README.md 各子小节内维护，**本文件不再重复枚举**，避免双写漂移。

3. **快速通道（命中即终止步骤 2）**：仅当路由到 **1.1 SRE Team** 时优先尝试，按以下顺序检查 `references/technology-center/InfrastructurePlatformDepartment.md` 的对应小节：
   1. **22 类高频工单速查表** (`### 常见问题排查（速查表 + 历史工单 22 类高频问题）`)：覆盖发布 / EKS / EC2 / 网络 / 域名 / DB / Redis / Canal / Kafka / Apollo / 网关 / 告警 / 监控 / JumpServer / 大数据 / LiteLLM / CI / 云权限 / 办公 IT 等。**优先级最高**，命中即返回。
   2. **Gitlab 专项** (`### Gitlab 专项负责人地图`)：覆盖 Gitlab 权限 / Code Review / GPG / 安全卡点 / Merge 报错 / 接口限制申请 / 发布检测白名单。
   3. **公共组件专项** (`### 公共组件找人专项指引`)：覆盖 Jedis / RPC / 业务网关 / 内部网关 / Kafka / RocketMQ / ETCD / nacos / Apollo / Skywalking / 三方风控 / 多泳道 / 探针体系（默认团队负责人 @Petter Li）。
   - 命中即结束步骤 2；未命中则进入子步骤 4。

4. **加载部门详情**：根据子步骤 2 的路由结果，阅读 `references/technology-center/InfrastructurePlatformDepartment.md` 中对应的 H2/H3 小节（1.1 / 1.2 / 1.3 三个方向均在同一文件）。

5. **定位负责人（粒度优先级）**：按以下顺序输出负责人，**只取一个粒度的结果，不混用**：
   1. 若详情文件中明确写出"具体系统负责人"或表格行级负责人（如 22 类速查表的某一行），**优先返回该具体负责人**。
   2. 若仅有"团队负责人"，返回该团队负责人。
   3. 若条目同时给出"主负责人 / 备份负责人"列表（如 22 类速查表）：
      - **主值班人 = 主负责人列表的第一个**（与步骤 1 规则保持一致）。
      - 若用户明确要求"备份/二线/紧急联系人"，则返回备份负责人列表的第一个。
   4. 若条目附注"紧急找 @X"或"紧急联系 @Y"：仅当用户问题中包含 **P1 / P0 / 紧急 / 故障 / 生产事故 / Down / 不可用** 等紧急关键词时附带返回紧急联系人，否则不返回。
   5. 若一个人同时挂多职责（如 `@Hugo Deng` 同时负责签名机与 MPC），**保留全部职责描述**一并返回，避免误判范围。

6. **分支逻辑**：如果"快速通道"（子步骤 3）与"定位负责人"（子步骤 5）均无法匹配到合适负责人，立即终止当前步骤，跳转至 **步骤 3**。

### 步骤 3：查询知识库 (最终兜底)

如果 **步骤 1** 和 **步骤 2** 均无结果，调用 `search_knowledge_base` 工具兜底：

- **入参构造**：将用户原始问题中的核心名词（系统名 / 业务名 / 故障现象）拼成 query 字符串。
- **结果筛选**：取返回结果中**置信度最高且明确包含负责人姓名**的条目；若所有条目置信度均低或不含明确负责人，视为兜底失败，进入 **步骤 4**。

### 步骤 4：人工分配兜底（终极兜底）

当 **步骤 1 / 2 / 3 全部失败**时，把问题升级到人工分配：

- **兜底负责人**：**@Sunway Zhong**（负责接单后人工判断并分配到对应负责人）。
- 直接使用《注意事项》中的"失败兜底"文案回复，**必须在文案中明示已指派 @Sunway Zhong 进行人工分配**，避免用户卡在"找不到人"状态。

## 输出格式

当你向用户回复最终结果时，**必须严格遵守**以下排版规范：
- **【严禁标题】**：绝对不允许使用 `#`、`##` 等任何级别的 Markdown 标题。
- **【极简汇报】**：仅输出客观结果，**绝对禁止**输出"下一步建议"、"可选操作"、"温馨提示"等附加段落。
- **【结构化引导】**：使用加粗文本引导结果区块。
- **【数据真实性】**：仅输出数据源中**真实存在**的字段（姓名为 `@姓名`）。**当前数据源不含邮箱、电话、Slack 等联系方式，禁止编造**；如用户索取联系方式，回复"请通过 IM 搜索 @姓名 直接联系"。
- **【语种一致】**：默认中文回复。若用户提问全程使用英文，可切换为英文回复，但**姓名格式 `@Name` 保持原样不翻译**。

**标准输出模板（按场景选择其一）**：

**场景 A：仅询问"谁负责"**
```
**匹配结果：** 已为您匹配到 `<模块或方向>`，当前主负责人为 **@姓名**。
```

**场景 B：用户要求建单/拉群（步骤 1 路径）**
```
**匹配结果：** 已为您匹配到 `<模块>` 模块，当前主值班人为 **@姓名**。
**执行状态：** 已自动为您创建工单群并拉入值班人员，请在群内跟进处理。
```

**场景 C：返回主备或多人**
```
**匹配结果：** 已为您匹配到 `<方向>`，主负责人 **@姓名 A**；备份联系人 **@姓名 B**。
```

**场景 D：歧义无法消解，需用户二选一（如中间件实例 vs SDK）**
```
**匹配结果：** 您的问题涉及 `<中间件名>`，但未明确具体场景，请您确认后再继续：
- 若属于**实例运维**（broker 不可用 / 集群异常 / 网络不通 / Topic 管理），主负责人 **@姓名 A**。
- 若属于**SDK 使用**（客户端代码 / 消费积压 / 发送 timeout / 序列化），主负责人 **@姓名 B**。
**下一步：** 请补充具体描述，我将为您精确路由。
```

## 示例

1. 调用 `/oncall --list`，命中模块 `dba`。
2. 调用 `/duty dba`，主值班人 **@张三**。
3. 用户明确要求拉群，调用 `/oncall dba 数据库连接异常排查`。

**最终回复（场景 B）：**
**匹配结果：** 已为您匹配到 `dba` 模块，当前主值班人为 **@张三**。
**执行状态：** 已自动为您创建工单群并拉入值班人员，请在群内跟进处理。

## 注意事项

- **状态隔离**：每个步骤之间的工具调用结果仅作为你思考的上下文，不要将中间过程的大段 JSON 返回给用户。
- **失败兜底**：如果步骤 1 / 2 / 3 均无法定位到负责人，请严格使用以下文案回复，不得随意发挥：

  > **查询结果：** 抱歉，暂时无法匹配到对应的负责人。已指派 **@Sunway Zhong** 进行人工分配，请同步将问题描述发给 @Sunway Zhong，或提供更具体的业务线名称以便重新匹配。
- **上下文复用**：在执行 `/oncall` 建单时，自动从用户的原始提问中提取 `<title>`，切勿反问用户"工单标题是什么"。
- **路径冲突时步骤 1 优先**：若用户问题既能命中 `/oncall --list` 中的模块，又对应步骤 2 的快速通道（如同时存在 `gitlab` 模块与"Gitlab 专项"），按工作流程开头的优先级，**先走步骤 1**。
